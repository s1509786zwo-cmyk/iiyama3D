## 0. 前提：リポジトリには既存のゲームが存在しませんでした

作業開始時点の `main`（`8b7c782`）の内容は `README.md`（11 バイト）のみで、コード・アセット・
履歴は一切ありませんでした（`git ls-tree -r origin/main` で確認）。

そのため「既存のゲーム機能を壊さない」という要件に対しては、
**既存機能を破壊する変更は発生し得ない**一方で、**既存ゲームへ追加する作業もできませんでした**。
本実装は「タイトル → マップ選択 → 難易度選択 → 一人称探索（敵 AI・HP・リザルト・セーブ・
リトライ）」という最小構成のゲームを新規に用意し、そこへ 4 マップを組み込んだものです。
もし別リポジトリにゲーム本体がある場合は、`src/game/flow.js` と `assets/maps/manifest.json` を
移植する形で統合できます。

**ファイル参照 / 読み込み状態 / プレビュー / 衝突判定 / 開始地点 / 開始方向 / 倍率** を

|---|---|---|---|---|

| warehouse | 102,367 | 137×56 中 6,181 | ワールド原点 | 315.0° |
| subway | 85,799 | 24×64 中 714 | ワールド原点 | 142.5° |

開始地点は「地形を実際にレイキャストして、天井高 1.8 m 以上・体の周囲 0.28 m 以上が空いて

かつ見通し距離が最も長いセル**を自動選定しています（マップごとに個別計算、共通座標の
使い回しなし）。開始方向は 48 方位を走査し、直近の見通しが最も長い向きを採用しています。

## 4. マップ選択画面

* 4 枚のカードに、**実モデルからレンダリングしたプレビュー画像**（`assets/maps/previews/*.webp`、
  ゲームと同一の変換・同一の目線高でレンダリング）、**ファイル名**、選択状態、読み込み状態
  （未読み込み／読み込み中／読み込み済み／失敗）を表示。
* 選択すると ID を保持し「次へ」が有効化 → 難易度選択へ遷移。
* 読み込みに失敗したマップはカードが赤枠＋エラー文になり、選択不可。開始もできません。
* **別マップでの代用は行いません**（`flow.startGame` が ERROR 状態を検出して開始を拒否、
  そのことをテストで確認）。

## 6. 衝突判定と移動

* 元モデルに衝突判定データは含まれていませんでした（glTF に物理データなし）。そこで
  **描画メッシュそのものから衝突用メッシュを生成**しています（見た目とのズレがない）。
* 生成規則: 極小スリバー三角形のみ除去し、上限 16 万三角形に収まるよう適応的に閾値調整。
  ノード変換を適用した最終ゲーム座標系でベイク。three-mesh-bvh で BVH 化。
* プレイヤーはカプセル近似（足元・腰・頭の 3 高さ × 16 方向レイ）で壁を検出し、
  **壁ずり（スライド）と段差の自動昇降**を行います。
* 床の法線が裏返っているスキャンモデル（classroom で実際に発生）でも立てるよう、
  ヒット法線はレイ方向に対して向きを補正しています。

### 実行した物理テスト（4 マップ共通、`npm run test:game`）
* 開始地点で 2 秒静止 → 落下しない（`onGround=true`、y 変動 < 0.35 m）
* 前進 2 秒 → 2.39 m 移動し、床の上に留まる
* 走って 8 方向へ 4 秒ずつ突進 → **マップ外への脱出 0/8**（外周をすり抜けない）
* 開始地点のカプセル内にジオメトリが無い（壁・障害物の内部スポーンでない）

## 9. 実際に確認できたこと / できなかったこと

### 確認できた（この環境で実行済み）
1. Drive から 4 ファイルを取得し、MD5 が一致する … `docs/provenance.json`
2. 4 ファイルが GLB として解析できる … 統合テスト（three.js GLTFLoader）
3. 4 マップが個別に登録される … 統合テスト + wiring テスト
4. マップ選択画面に正しいファイル名・状態・プレビューが出る … jsdom + 実 index.html で検証
5. 選択したマップがゲームに読み込まれる（ID 保持・代用なし）… 統合テスト
6. テクスチャ・マテリアルが保持されている … `verify:assets` / `verify_draco`
7. プレイヤー寸法・目線高が全マップ共通 … wiring テスト
8. 床・壁・障害物の衝突判定が機能する … 物理テスト（静止・歩行・8 方向脱出試験）
9. 開始地点が妥当（床の上・内部でない・落下しない）… 統合テスト + nav 照合
10. 画面遷移・リトライ・セーブ・敵 AI の経路探索 … 統合テスト（97/97 PASS）

### 確認できなかった（明示）
* **GPU 描画そのもの**。このサンドボックスにはブラウザが無く（Chromium の起動に必要な
  libnss3 等が導入できず、パッケージ取得も不可）、WebGL の実描画・フレームレート・
  実機での見た目は未確認です。代わりに、ゲームと同一の変換行列・同一目線高で
  オフラインレンダラ（`tools/render_mesh.py`）により各マップのプレビュー画像を生成し、
  目視で構図を確認しました。
* ポインタロックやマウス感度など、ブラウザ固有の操作感。
* 実 GPU での VRAM 使用量（特に subway は 4096² テクスチャを含むため、デコード後
  約 500 MB 程度になります）。もし描画が重い場合は、解像度を落とすのではなく
  `assets/maps/manifest.json` の該当マップに将来 `textureMaxDimension` を設定する
  拡張余地を残しています（現状は未使用＝原寸のまま）。

## 10. 既知の制限

* 敵 AI は nav グリッド上の経路探索＋直線視認で、ドアの開閉などのギミックはありません。
* ゲームの目的は「90 秒生存」のシンプルなものです（既存ゲームが無かったため）。
* 元の GLB 原本（208 MB）はリポジトリに含めていません。`assets/maps/models` の変換版が
  実体で、`tools/build_assets.py` + `tools/draco.mjs` + `tools/bake.py` により
  Drive の fileId から再取得 → 同一手順で再生成できます。
