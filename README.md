# IIYAMA 3D — 廃墟探索

Google Drive に保存されていた **4つの GLB マップ** を読み込み、一人称視点で探索するサバイバルゲームです。
マップは Google Drive から取得して **プロジェクト内 (`public/maps/`) に保存** してあるため、実行時に Google Drive へアクセスする必要はありません。

```
npm install
npm run dev        # http://localhost:5173
```

---

## 2. 操作方法

| キー | 動作 |
|------|------|
| `W A S D` / 矢印 | 移動 |
| マウス | 視点（画面クリックでマウス固定） |
| `Shift` | ダッシュ（スタミナ消費） |
| `Space` | ジャンプ / 段差の乗り越え |
| `F` | フラッシュライト ON/OFF |
| `Esc` | ポーズ（再開 / リトライ / マップ選択 / タイトル） |

**目的**: マップ内に散らばる「記録」をすべて回収 → 開始地点が脱出地点として起動 → 戻って脱出。
敵に見つかると追跡され、接触でダメージ。体力が尽きると失敗。

## 3. 画面の流れ

```
タイトル → マップ選択 → 難易度選択 → 読み込み → ゲーム
                                   ↑                ↓
                              リトライ ← リザルト（成功 / 失敗）
```

- **マップ選択**: カードごとに「実際の3Dモデルを描画して生成したプレビュー画像」「Google Drive の元ファイル名」「選択ボタン」「選択状態」「読み込み状態」を表示。
  読み込みに失敗したマップは赤いエラー表示になり **選択できません**（他のマップで代用しません）。
  一度生成したプレビューは IndexedDB にキャッシュされ、2回目以降は即時表示されます。
- **難易度**: 静穏 / 標準 / 苛烈（敵の数・速度・発見距離・ダメージ・初期体力が変化）。
- **セーブ**: ベストタイム・脱出回数・挑戦回数・設定を `localStorage` に保存。

## 4. 設計

### 4.1 マップレジストリ（マップ追加はここだけ）

`src/maps/mapData.js` の `MAP_DEFS` に1件追加するだけで、**マップ数を4に固定せず** 新しいマップを追加できます。
マップID・ファイル参照・縮尺・開始地点・衝突判定・ナビゲーションは個別管理です。

```js
{
  id: 'my_new_map',
  name: '新しいマップ',
  file: 'maps/my_new_map.glb',
  sourceFile: 'my_new_map.glb',
  driveFileId: '...',
  ...
}
```

`src/maps/baked.json`（衝突・ナビ・開始地点のベイク結果）も同名キーで追加します。
ユーザーが指示していないファイルを勝手にマップへ追加することはありません。

### 4.2 縮尺の校正（マップごとに個別、共通倍率は使っていません）

| マップ | 単位系の判定 | 根拠（実測） | 倍率 |
|--------|--------------|--------------|------|
| city_street | 既にメートル | 床 y=-0.05 / 扉上部 1.95 / 建物 2.6–5.5 | ×1.0 |
| warehouse | 既にメートル | 床 -2.95 → 天井 +3.35 = 6.3 m | ×1.0 |
| subway | センチメートル | 床 4 → 天井 291 = 287 cm = 2.87 m | ×0.01 |
| classroom | インチ（SketchUp 書き出し） | 床 0.3 → 天井 113.7 = 113.4 in = 2.88 m | ×0.0254 |

倍率はモデル全体に対する **均一スケール** のみ（縦横比は不変）。
プレイヤーは全マップ共通で **身長 1.75 m / カプセル半径 0.24 m / 眼高 1.62 m**。

### 4.3 衝突判定とナビゲーション

- 読み込み時にシーン全体を1つのジオメトリへ統合し、**BVH (`three-mesh-bvh`)** を構築（数百〜130万ポリゴンでも実用的）。
- プレイヤー／敵は **カプセル** としてBVHに押し出し解決（壁・柱・机・棚を通り抜けない）。0.45 m までの段差は自動で乗り越え。
- 敵の経路探索用に、実ジオメトリから **0.35 m グリッドの歩行可能マップ** を事前ベイク（`tools/bake.mjs`）し、A* + 直進で移動。
- 見た目と衝突判定がずれないよう、歩行グリッドも BVH のレイキャストから生成しています。

### 4.4 開始地点

`tools/bake.mjs` が各マップの実ジオメトリを解析して **マップ固有の開始地点と開始方向** を決定します。

- 床が存在し、立ち上がれる空間（0.5 / 1.0 / 1.5 m の3高度でクリアランス確認）がある
- 最大連結領域の中から、壁から距離があり、フットプリント中央に近いセル
- 開始方向は「前方が最も開けている方位」（水平32方向のレイキャストで決定）

| マップ | 開始位置 (x, y, z) | 開始方向 (yaw) |
|--------|--------------------|----------------|
| city_street | (-2.90, -0.18, -2.56) | -3.14 rad |
| warehouse | (2.10, -2.93, -6.87) | -2.55 rad |
| subway | (-0.17, 0.04, -6.04) | -3.14 rad |
| classroom | (3.00, 0.01, -4.96) | 0.39 rad |

落下した場合は自動で開始地点へ戻ります。

### 4.5 アセットの保存と「無劣化」の検証

Google Drive の GLB は `tools/build-assets.mjs` でプロジェクト用に変換しています（合計 212.3 MB → 115.8 MB）。
**見た目を変えない変換のみ** を行い、すべて機械的に検証しています（`tools/verify-assets.mjs`）。

| 変換 | 内容 | 検証結果 |
|------|------|----------|
| テクスチャ | PNG → **可逆 WebP**（解像度・画素値そのまま） | 全テクスチャで画素完全一致（`texturesPixelIdentical=true`） |
| ジオメトリ | **可逆** meshopt 圧縮 (`EXT_meshopt_compression`, FILTER) | ワールド空間の三角形集合が完全一致（四半精度で比較） |
| マテリアル | warehouse のみ `KHR_materials_pbrSpecularGlossiness` → metal/rough（three.js が spec/gloss 非対応のため必須） | 三角形は完全一致 / 拡散テクスチャは全26枚保持 / 頂点カラー・UVは不変 |
| 未使用リソース | `dedup` のみ（`prune` は参照中テクスチャを落とすバグがあるため不使用） | 参照テクスチャ欠落なし |

- ポリゴン削減・解像度変更・再デザインは一切していません（三角形数は4マップすべて元と同一）。
- 同梱ファイルは Khronos の glTF Validator で **エラー0 / 警告0** です（`tools/validate-glb.mjs`）。
- 元ファイル（212 MB）は容量制限のためリポジトリには含めていません。再変換は元GLBを `google_drive/` に置いて `npm run assets:build`。

## 5. ゲーム機能

- タイトル画面、マップ選択、難易度選択、リザルト、ポーズ
- 一人称移動・視点・ダッシュ・ジャンプ・フラッシュライト
- 敵AI（巡回 → 視認で追跡 → 見失うと捜索 → 巡回。壁抜け不可・A*経路）
- 記録の回収と脱出、体力・スタミナ、ダメージ演出
- セーブ（ベストタイム／回出撃数／設定）、リトライ、マップ選択へ戻る

## 7. 既知の制約

- ブラウザ上での目視確認（描画の見た目・操作感）は、この開発環境にブラウザが無いため未実施です。ロジック・アセット・読み込み経路はヘッドレスで検証済みです。
- マップ選択の初回表示時は、4モデル（約116MB）を順に読み込んでプレビューを生成するため時間がかかります（2回目以降はキャッシュ）。
- シャドウマップは負荷対策のため無効（フォグ＋実ライト＋フラッシュライトでライティング）。
- 本リポジトリには元からゲーム実装が存在しなかったため（初期コミットは README のみ）、本作は新規に実装しています。
